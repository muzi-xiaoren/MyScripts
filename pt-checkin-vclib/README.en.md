# PT 签到 · VC-Lib

Whenever you open any [pt.vclib.online](https://pt.vclib.online/) page, this reduces the daily check-in (签到, for magic/bonus points) to "type 6 characters":

- **Not checked in yet** → a small panel appears in the middle of the page you're on, showing the site's own captcha image (scaled 2x with a contrast filter, so it's easy to read); type all 6 characters and it submits itself, then the page reloads once the check-in goes through.
- **Already checked in** → nothing happens: no panel, no reload.

## Why this site can't be fully automated

VC-Lib's check-in page uses NexusPHP's **classic image captcha**: a distorted-character image generated by `image.php`, plus an `imagestring` text field and an `imagehash` hidden field, POSTed back to `attendance.php`.

That puzzle exists to confirm there's a human at the screen. **Having the script read it would defeat exactly that, so this script doesn't do it** (and it doesn't call any captcha-solving service either).

So the split is: everything that can be automated is — checking whether today is done, pulling the captcha into the page you're already looking at, submitting, deciding whether it worked, reloading. **The only thing left to you is reading the image and typing it.** Compared to the manual flow (navigate to the check-in page → find the field → type → click → navigate back), it saves two page loads and the hunting.

## Install

Install [Tampermonkey](https://www.tampermonkey.net/) first, then [click here to install the script](https://raw.githubusercontent.com/muzi-xiaoren/MyScripts/main/pt-checkin-vclib/pt-checkin-vclib.user.js).

## Usage

Open any page on the site → the panel shows up centered → type the characters → **it submits itself once all 6 are in** (Enter works too).

- **Can't read it**: click the captcha image for a new one. The image is already blown up to 300x80 with a contrast filter — that's to help *you* read it; the script does no recognition of any kind.
- **Typed it wrong**: it automatically fetches a fresh one (the `imagehash` has been consumed server-side, so the same image can't be resubmitted).
- **Not now**: click `×` in the corner — it stays hidden for this browser session (reopening the browser brings it back).
- The panel won't steal your keyboard focus — it only autofocuses when you aren't typing somewhere else.

## Config: where to go after check-in

`RETURN_TO` at the top of the script defaults to `''`, meaning just reload the current page. Set it to navigate somewhere fixed instead:

```js
const RETURN_TO = 'https://pt.vclib.online/torrents.php';
```

Two more knobs sit at the top of the script: `CODE_LENGTH` (captcha length — 6 on this site today; filling it auto-submits, and a smaller value can't get you stuck since Enter still works) and `IMAGE_SCALE` / `IMAGE_FILTER` (how much the captcha image is enlarged, and its filter).

## How it works

When the check-in is pending, the page header has `<a class="faqlink" href="attendance.php">[签到得魔力]</a>`; after checking in, that link loses its `faqlink` class and the text becomes "已签到…". The script keys off that structure rather than the wording (which differs per site).

When a check-in is due it fetches `/attendance.php` in the background and takes the captcha image URL and the `imagehash` from that same response — they must come from one request, since the server stores the answer keyed by hash, which is also why "new image" refetches the whole check-in page instead of just reloading the image. Once the code is filled in it POSTs `imagehash` + `imagestring` back to `attendance.php` and decides success by whether the check-in link is still present in the response (again, structure, not wording). On success it writes a per-day `localStorage` flag so you're only prompted once a day.
