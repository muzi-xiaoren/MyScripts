# 蒸汽同步 SteamSync

把 [Steam 年度回顾](https://store.steampowered.com/replay/)和全部游戏的累计游玩时长上传到 GitHub 仓库，多个账号合并成一张游戏总表。

当前版本：`1.0.1`。

## 功能

- 在 Steam 商店顶部导航「客服」右侧加入两个入口：
  - 「年度回顾」：跳转到当前账号的年度回顾页面。
  - 「GitHub 同步」：打开配置面板，点击外部或按 Escape 关闭。
- 填写 GitHub Token、仓库地址，以及可选的分支（默认仓库默认分支）和文件目录（默认 `steam`），点击「上传」。
- 「只重新生成总表」不读取 Steam，只用仓库里已有的数据重新生成总表。

## 上传内容

```
steam/
├── <SteamID>/
│   ├── replay-<年份>.json / .md     年度回顾，每年一份
│   └── lifetime-<时间戳>.json / .md 累计游玩时长快照，每次上传新建
└── index-<时间戳>.json / .md        所有账号合并的游戏总表，每次上传新建
```

- **年度回顾**：从 2022 年起逐年读取。往年的回顾内容不会再变，仓库里已有的年份直接跳过，只补缺失的年份；当年的回顾要到年底 Steam 发布后才会出现。内容包括：
  - 全年总小时数、游戏数、当年新玩的游戏数、成就数。
  - 每个游戏的小时数、占比、是否当年新玩、首次游玩日期和平台，按小时数排名。
  - 每月总小时数和当月玩得最多的三个游戏。
  - 偏好标签及权重。
- **累计时长**：所有玩过的游戏的累计小时数、近两周时长、首次和最近游玩日期，包括以前通过家庭共享借玩、现在已不在库中的游戏。
- **总表**：合并仓库里所有账号的数据，同一个游戏只占一行。列出各账号的累计小时数、合计小时数、每年各账号回顾中的小时数之和和最早的首次游玩日期，按合计小时数排名。每个账号的累计时长取仓库里最新的一份快照。

Markdown 中的时长满一小时显示为小时（保留一位小数），不到一小时显示为分钟；JSON 里保留原始的秒数和分钟数。

多个账号分别登录后各上传一次即可。每次上传都会读取仓库里全部账号的数据重新生成总表，所以最后一次上传生成的总表总是包含所有账号。

## 数据来源

- 年度回顾页面里年度和单个游戏的总时长为空，但每个月都带有当月总秒数和每个游戏的秒数，脚本逐月相加得到全年的精确小时数。
- 累计时长来自 Steam 客户端使用的 `IPlayerService/ClientGetLastPlayedTimes` 接口，游戏名称来自 `IStoreBrowseService/GetItems`（简体中文），标签名称来自 `IStoreService/GetTagList`。
- 这些接口使用 Steam 页面自带的登录凭证，只读取当前登录账号的数据，不需要填写 Steam API Key。
- 2022 年以前没有年度回顾，那几年的游戏只有累计时长，没有分年数据。

## 安全

GitHub Token 以明文保存在油猴存储中，建议使用只授权目标仓库、只开放 Contents 读写的 fine-grained token（生成总表需要读取仓库）。上传前会检查 Token 是否以 `github_pat_` 或 `ghp_` 等前缀开头。输入框不使用登录表单的字段名和密码类型，避免浏览器把已保存的账号密码自动填进来。GitHub 请求不携带 Steam 的 Cookie，Steam 的登录凭证不会被上传或保存。

## 安装

安装 [Tampermonkey](https://www.tampermonkey.net/) 后，点击 [安装 SteamSync](https://raw.githubusercontent.com/muzi-xiaoren/MyScripts/main/steam-sync/steam-sync.user.js)。

## 验证状态

`1.0.1` 用仓库中三个账号的真实上传数据重新生成 Markdown，确认不到一小时的时长显示为分钟。`1.0.0` 已在已登录的真实 Steam 商店页面验证：导航入口位置与面板样式；读取 2023–2025 年回顾，仓库中已有的 2022 年被跳过；每年小时数与回顾占比一致；累计时长 67 个游戏，包括 38 个已不在库中的借玩游戏；与模拟的第二个账号合并生成总表，同一游戏合并为一行，只读取该账号最新的累计时长快照；「只重新生成总表」只提交总表文件。GitHub 读写为模拟接口。
